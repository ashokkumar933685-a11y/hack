Ride-Share Surge Pricing Replay

Problem Description

A ride-share company is replaying a stream of pricing logs to detect anomalies. Each log entry is a ride request with a timestamp t (in seconds since a fixed reference epoch) and a fare f (in cents). The pricing-fairness team has a question: for every ride in the log, was its fare in the "top 10%" of fares charged within the past 5 minutes (300 seconds)?

Concretely: ride i is "flagged as surge-anomalous" iff its fare f_i is strictly greater than the 90th percentile of fares in its window — the current ride together with every earlier ride whose timestamp lies in (t_i − 300, t_i] (a half-open window ending at t_i, looking back 300 seconds). Rides are replayed in the order given, which is chronological; when several rides share a timestamp, their listed order is their order in time. The 90th percentile is computed using the "nearest-rank" convention: with n rides in the window, the 90th-percentile fare is the fare of the [0.9 × n]-th ride after sorting the window's fares in ascending order. The current ride i itself counts toward the window (so n ≥ 1).

Small windows never flag (by design). Since the current ride is part of its own window and [0.9 × n] = n for every n ≤ 9, the 90th-percentile fare for those sizes is exactly the window's maximum — and a ride can never be "strictly" greater than a maximum it belongs to. So whenever a ride's window holds fewer than 10 rides, its output is 0. The earliest a ride can be flagged is when its window contains at least 10 rides, where k = [0.9 × 10] = 9 gives a genuine percentile cutoff below the maximum. This is intended behavior, not an edge case to "fix".

Output, for each ride in chronological order, 1 if it is surge-anomalous, 0 otherwise.

Input

  • N — number of rides
  • rides[i] = (t_i, f_i) — timestamp (seconds since a fixed reference epoch) and fare (cents)
  • Rides are given in non-decreasing order of timestamp; multiple rides may share the same timestamp

Input Format

N
t_1 f_1
t_2 f_2
...
t_N f_N

Detailed Format:

  • Line 1: N
  • Lines 2..N+1: each line contains t_i f_i, with 0 ≤ t_i ≤ 10^9 and 1 ≤ f_i ≤ 10^9

static bool parse_input(InputData &D) {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    if (!(cin >> D.N)) return false;
    D.times.assign(D.N, 0);
    D.fares.assign(D.N, 0);
    for (int i = 0; i < D.N; ++i) cin >> D.times[i] >> D.fares[i];
    return true;
}

static void format_output(const vector<int> &flags) {
    // One 0/1 flag per ride, one per line.
    for (int f : flags) cout << f << "\n";
}
